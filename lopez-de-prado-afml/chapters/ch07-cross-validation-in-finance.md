# Chapter 7: Cross-Validation in Finance

> **Source**: Marcos López de Prado, *Advances in Financial Machine Learning*, Wiley 2018 | Chapter 7, pp. 103–112

## Core Idea

Standard k-fold cross-validation is **dangerous for financial time series** because of *serial dependence* and *information leakage* between train and test sets. The chapter introduces **purged k-fold cross-validation with embargo** and **combinatorial purged cross-validation (CPCV)**, which address these failures. The key insight: every fold must be **information-purged** (no observation in the test set can be informed by an observation in the train set) and the test set must be **embargoed** (a gap between train and test to prevent leakage of the target's serial dependence into the train set).

This is the single most important methodology in the book for any agent that trains a model on financial data.

## Frameworks Introduced

- **Purged k-fold cross-validation**:
  - Like standard k-fold, but the test set is *purged* of any observation that overlaps in time with the train set (i.e. observations whose `t_0, t_1` interval overlaps with any train observation's interval).
  - And the test set is *embargoed* — a gap of 1% of the total sample size (or 1 day) is left after the test set to prevent leakage of the target's serial dependence.
  - *When to use*: every time you train a model on financial time series. **Standard k-fold is wrong for finance.**
  - *Why it works*: addresses the two specific failure modes of standard k-fold on financial data — temporal leakage (train and test overlap in time) and serial dependence (the test set's target is correlated with the train set's features).
  - *Failure mode*: if the dataset has very long serial dependence (e.g. multi-year half-life of an autocorrelation), the embargo must be set accordingly; the default 1% may be too short.

- **Combinatorial Purged Cross-Validation (CPCV)**:
  - CPCV generalises purged k-fold. With N folds and k = N / 2, CPCV generates `N_paths = C(N, k) = N! / (k! (N−k)!)` distinct backtest paths.
  - Each path is a train-test combination, with purging and embargo applied.
  - For N = 6, k = 3: `N_paths = 6! / (3! 3!) = 20` distinct paths.
  - *When to use*: when you need *many* backtest paths to estimate the distribution of strategy performance. CPCV gives you 20 paths from 6 folds; standard purged k-fold gives 6.
  - *Why it works*: more paths means a better estimate of the *distribution* of the OOS performance, not just a point estimate. This is the foundation of the DSR and PBO statistics (ch14).
  - *Failure mode*: with very correlated folds, CPCV paths are not independent; the effective sample size is smaller than the nominal N_paths.

- **Backtest paths from CPCV (the path generator)**:
  - For N = 6, k = 3, the 20 paths are: {T1, T2, T3, T4}, {T1, T2, T3, T5}, ..., where each `Ti` is a contiguous time period.
  - The number of paths is `C(N, k) = 20` (for N=6, k=3). The general formula is `C(N, k) = N! / (k! (N−k)!)`.
  - For N = 10, k = 5: `C(10, 5) = 252` paths.

- **The Embargo Fraction**:
  - The default embargo is 1% of the total sample size; for daily data and 2500 days, this is ~25 days.
  - For high-frequency data, the embargo is 1 day (the minimum to prevent label leakage).
  - *Why it matters*: too short an embargo leaks information; too long an embargo wastes data.

## Key Concepts

1. **Information leakage** — when the test set's target is informed by the train set's features (or vice versa). Standard k-fold allows this on time series.
2. **Purging** — removing from the test set any observation that overlaps in time with the train set.
3. **Embargo** — a gap between train and test to prevent serial-dependence leakage.
4. **CPCV paths** — the distinct backtest paths generated by combinatorial purged CV.
5. **Backtest path** — a single train-test combination that produces one OOS performance number.
6. **Distribution of OOS performance** — the histogram of backtest-path Sharpes (or other metrics); the basis for the DSR and PBO.
7. **Walk-forward optimisation** — a simpler, sequential version of purged CV; the embargo is built in.
8. **The triple-barrier labeling** (ch03) — defines the `t_0, t_1` interval used in purging.
9. **The information ratio's empirical distribution** — the histogram of backtest-path IRs; the metric for confidence in a strategy.

## Formulas & Reference Tables

**Number of CPCV paths**

`N_paths = C(N, k) = N! / (k! (N−k)!)`

For N = 6, k = 3: N_paths = 20. For N = 10, k = 5: N_paths = 252. For N = 16, k = 8: N_paths = 12870.

**Purging rule (for triple-barrier labels)**

For a train set with labels at indices `i` and a test set with labels at indices `j`:
- Purge `j` from the test set if `t_0(j) < t_1(i) AND t_0(i) < t_1(j)`.
- I.e. the test observation's interval overlaps with the train observation's interval.

**Embargo fraction**

`embargo = ceil(pct_embargo × T_total)`

Default `pct_embargo = 0.01` (1%). For high-frequency data, use 1 day.

**Walk-forward optimisation (sequential)**

`(train_1, test_1), (train_2, test_2), ..., (train_N, test_N)` where `train_{i+1} = train_i + delta_1` and `test_{i+1} = test_i + delta_2` (typically `delta_1 = delta_2 = T / N`).

**The empirical distribution of OOS Sharpe**

For a strategy with mean OOS Sharpe `μ_OS` and standard deviation `σ_OS` across the N_paths, the 95% confidence interval is `μ_OS ± 1.96 × σ_OS / √N_paths`. With CPCV and N_paths = 20, the 95% CI is `μ_OS ± 0.44 × σ_OS`.

## Mental Models

- **Standard k-fold is wrong for finance.** The serial dependence and the labelling rules make standard k-fold leak information; the agent must use purged k-fold or CPCV.
- **The embargo is the time-buffer that prevents leakage.** The default 1% is a reasonable starting point; the agent should test the sensitivity.
- **CPCV is the multi-path version of purged k-fold.** It gives the *distribution* of the OOS performance, not just a point estimate; this is what the DSR and PBO need.

## Worked Example (RECOMPUTED)

*Setup.* 10 years of daily data, 2520 observations. The strategy uses triple-barrier labels with 5-day holding period. Want to do 6-fold purged CV with 1% embargo.

*Step 1 — Number of CPCV paths*.
- N = 6, k = 3 → N_paths = 20.

*Step 2 — Embargo size*.
- `T_total = 2520`; `pct_embargo = 0.01`; `embargo = ceil(0.01 × 2520) = ceil(25.2) = 26 days`.
- The embargo is ~5 business weeks.

*Step 3 — Purge set for a single fold*.
- A 5-day holding period means the label at observation `t` is `t_0 = t, t_1 = t + 5`.
- For a train set ending at `t_train_end = 420` (1/6 of the sample) and a test set starting at `t_test_start = 420 + 1` (next day):
  - Observations in the test set with `t_0 < 420 + 5 = 425` overlap with train labels and must be purged.
  - The first 5 days of the test set are purged.
- For a train set ending at `t_train_end = 420` and a test set starting at `t_test_start = 2520 − 420 + 1 = 2101`:
  - No overlap; no purging needed.

*Step 4 — Walk-forward sanity check*.
- 6 folds, each of length 420, with embargo 26 days.
- 5 walk-forward steps, each producing 1 OOS Sharpe.
- Average OOS Sharpe `μ_OS = 0.4`; standard deviation `σ_OS = 0.6` (over the 5 walk-forward OOS Sharpes).
- 95% CI: `0.4 ± 1.96 × 0.6 / √5 = 0.4 ± 0.53 = [−0.13, 0.93]`. **The 95% CI includes 0**, so the strategy is not statistically significant at the 5-step walk-forward level. The agent should not allocate capital.

*Step 5 — CPCV vs walk-forward*.
- CPCV with 20 paths gives a 95% CI of `μ_OS ± 1.96 × σ_OS / √20 = 0.4 ± 0.26 = [0.14, 0.66]`. **The 95% CI no longer includes 0**, but the lower bound is only 0.14 — a strategy with SR ~ 0.14 is barely worth the cost of trading. The agent should *not* allocate significant capital.

*Sanity check (Python).*
```python
import math
N, k = 6, 3
N_paths = math.comb(N, k)
print(f"CPCV paths: {N_paths}")        # 20
T = 2520
embargo = math.ceil(0.01 * T)
print(f"Embargo: {embargo} days")      # 26

mu, sigma, n = 0.4, 0.6, 5
ci95_wf = (mu - 1.96*sigma/math.sqrt(n), mu + 1.96*sigma/math.sqrt(n))
print(f"95% CI walk-forward: {ci95_wf}")

mu, sigma, n = 0.4, 0.6, 20
ci95_cpcv = (mu - 1.96*sigma/math.sqrt(n), mu + 1.96*sigma/math.sqrt(n))
print(f"95% CI CPCV      : {ci95_cpcv}")
```

## Anti-patterns

- **Using standard k-fold on financial time series.** Always use purged k-fold or CPCV.
- **Setting the embargo to zero.** Even a small embargo (1 day) prevents the most obvious leakage.
- **Trusting a single OOS number from a single train-test split.** The OOS number is a *sample*; the *distribution* of OOS numbers is what matters.
- **CPCV with too few paths.** N_paths = 6 is barely informative; the agent should use N ≥ 6, k = N/2 to get ≥ 20 paths.

## Practitioner Notes

- **2026 update.** The CPCV framework is now standard; `mlfinlab` and `vectorbt` implement it. The companion paper (Bailey, Borwein, López de Prado & Zhu 2016, "The Probability of Backtest Overfitting") is the canonical reference.
- **Walk-forward** is the simpler alternative; use it when the data is too small for CPCV (e.g. < 5 years of daily data).
- **Nested cross-validation** is the extension for hyperparameter tuning: an inner loop for hyperparameter selection, an outer loop for performance estimation.
- **The embargo is not optional.** The López de Prado experiments show that without embargo, the DSR is inflated by ~30% in the presence of serial dependence.

## Key Takeaways

1. **Standard k-fold is wrong for finance.** Use purged k-fold or CPCV.
2. **Purging** removes test observations that overlap in time with train observations.
3. **Embargo** prevents leakage of the target's serial dependence; the default is 1% of the sample size.
4. **CPCV** is the multi-path version; for N=6, k=3 it gives 20 backtest paths.
5. **The distribution of OOS Sharpe is what matters**, not a single OOS number.
