# Axe 6 — ML panel diagnostics (logreg + purged k-fold + DSR) — conclusion : 0 edge tradable clair

**Date** : 2026-10-15
**Statut** : AXE CLOS. Aucun ledger hypothesis enregistré.
**Skills mobilisés** : `lopez-de-prado-afml` (ch03 labeling, ch04 sample weights, ch07 purged k-fold, ch14 DSR), `quant-backtest-hygiene` (ch04 look-ahead, ch05 walk-forward, ch09 DSR).

## 1. Question de recherche

*Peut-on construire, à partir des klines 1m daily agrégées sur le panel BTC/ETH/BNB/SOL pré-2024-07-01, un set de 8 features microstructurelles (causales) qui, via une régression logistique L2 sous purged k-fold CV + embargo, **bat** deux baselines triviales (classe majoritaire, signe du log-return d'hier) sur un OOS fixe de queue, et dont la performance passe le DSR (Bailey & López de Prado 2014) au seuil 0.05 ?*

La question est **falsification-first** : si le pipeline ML ne bat pas les baselines triviales, il n'a aucune chance d'être tradable net de coûts. C'est la leçon attendue des axes 1-4 (2026-10-14) et la cause structurelle documentée dans `EXPLORATION_JOURNAL.md` (klines 1m moyennent l'information microstructurelle).

## 2. Mécanisme (hypothétique)

Si un signal microstructurel existe sur klines 1m daily, il devrait être capturable par : (a) range normalisé par ATR (volatilité relative), (b) asymétrie close-open (sentiment court terme), (c) persistance de signe de retour (momentum 1-day), (d) ratio de variance 5j/1j (structure de cluster), (e) vol-of-vol (régime), (f) z-score 20j (mean-reversion).

## 3. Prédiction chiffrée (enregistrée avant de lire le résultat)

- **OOS hit-rate > max(majority class, sign baseline) + 3 pp** (règle de triage 1).
- **DSR p-value < 0.05** contre SR=0 avec n trials = len(λ) + 1 = 6 (règle 2).
- **CV best hit-rate > sign baseline CV hit-rate + 1 pp** (règle 3).

Si une des trois règles échoue → 0 edge tradable, l'axe klines-1m ML est clos.

## 4. Données et période

- Source : `aster.data.store.read("ohlcv", "binance", SYMBOL, "1d")`, klines 1m agrégées daily, lecture causale.
- Cutoff exploration : `2024-07-01T00:00:00Z`. Dev end : `2022-10-11T00:00:00Z` (80/20 IS/OOS).
- Symboles : `BTC/USDT`, `ETH/USDT`, `BNB/USDT`, `SOL/USDT` (4 actifs cross-section, 6353 obs bruts → 3543 obs après drop label neutre + drop NaN).
- Label : triple-barrière (AFML ch03) sur 5 jours, barrières horizontales à ±1×ATR(14), drop des touches verticales, binarisation +1 / -1.
- Features (8) : `log_return_1d`, `hl_range_norm_atr`, `co_asymmetry_norm_atr`, `realized_var_1d`, `sign_persist_1d`, `rv_ratio_5d_1d`, `vol_of_vol_5d`, `zscore_20d`.
- Modèle : régression logistique L-BFGS-B avec régularisation L2 ; λ ∈ {0.01, 0.1, 1, 10, 100} ; 200 itérations max ; perte logistique standard.
- CV : purged k-fold k=5 (AFML ch07) avec embargo = 6 jours (label window 5 + 1) sur les 80% IS.
- Preprocessing causal (AFML ch04, ch07) : z-score fit **sur le train fold uniquement** (expanding mean/std, min_periods=60), appliqué au test avec la dernière statistique train. Pas de fuite de preprocessing.
- OOS : 20% queue d'échantillon, jamais touché pendant la sélection de λ.

## 5. Tests lancés

- Purged k-fold IS pour choisir λ par hit-rate moyen.
- Refit sur les 80% IS avec le meilleur λ, score OOS fixe de queue.
- Baselines : (a) classe majoritaire OOS, (b) `sign(log_return_{t-1})` (momentum 1j), (c) classifieur uniforme [0,1] (aléatoire).
- DSR (Bailey & López de Prado 2014) : approximation normale ; n trials = 6 (5 λ + 1 OOS), n_obs = 6.
- BH-FDR : non applicable ici (1 seul test principal, pas une grille ; la correction pour essais multiples est dans le DSR via n_trials).
- Unit tests : 12 tests sur toy data (labeling, purged-fold, z-score causal, DSR sanity).

## 7. Application des règles de triage

- **Règle 1** (OOS hit > max(maj, sign) + 3pp) : 0.4350 vs 0.5791 → diff -0.1441 (**échec**, besoin ≥ +0.03).
- **Règle 2** (DSR p < 0.05) : 0.8837 (**échec**, besoin < 0.05).
- **Règle 3** (CV best > sign CV + 1pp) : CV best 0.5732 vs sign baseline 0.5323 → diff +0.0409, mais on n'a pas la CV du sign baseline fold-par-fold (le test a été construit comme un OOS fixe, pas un CV complet) ; même en supposant que cette règle passerait marginalement, les règles 1 et 2 sont les plus discriminantes et sont toutes deux violées.

**Verdict des règles** : 2/3 échouent, 1/3 marginale. **0 edge tradable net de coûts** (le gain brut de la baseline sign est de l'ordre de 0.5% par trade sur la triple-barrière, soit ~50 bps de mouvement attendu — déjà dominé par les 20 bps de frais aller-retour plus l'impact).

## 8. Faux positifs / leakages vérifiés

1. **Preprocessing look-ahead** : corrigé. La première version z-scorait sur l'ensemble du panel avant de splitter ; le résultat a été vérifié avec et sans la correction, et le lift OOS vs sign baseline reste dans la même fourchette (-0.090 → -0.097). Pas de fuite cachée.
2. **Embargo** : 6 jours = horizon du label + 1. Pour k=5 folds, chaque fold test exclut ±6 jours du train, garantissant qu'aucun label du train ne chevauche un label du test.
3. **Cutoff** : la fonction `_build_features` lève `ValueError` si l'index dépasse 2024-07-01. Test unitaire `test_build_features_rejects_post_cutoff` couvre ce contrat.
4. **Sélection de modèle** : n_trials=6 dans le DSR inclut 5 λ + 1 OOS. C'est conservateur (on aurait pu ignorer les λ intermédiaires), donc le p-value est légèrement gonflé vers 1. Si on avait pris n_trials=1 (OOS seul), le p-value resterait largement non significatif.
5. **Causalité des features** : test unitaire `test_build_features_shape_and_causal` vérifie que la première valeur définie de chaque feature coïncide avec la warmup attendue (ex. `zscore_20d` à iloc 19, `sign_persist_1d` > `log_return_1d`).

## 9. Leçon

1. **Les klines 1m daily ne contiennent pas de signal exploitable par un classifieur ML, même rigoureusement cross-validé et sans fuite de preprocessing.** Le pipeline (features → label → purged k-fold → logreg L2 → DSR) est mécaniquement correct (12 unit tests verts) et conclut 0 edge. C'est la confirmation indépendante, par une méthode ML rigoureuse, de la conclusion des axes 1-4 (2026-10-14) et de BACKLOG item 12.

2. **Le classifieur trivial `sign(log_return_{t-1})` (momentum 1 jour) bat la logreg entraînée** (53% vs 44% OOS). Le momentum 1-day sur crypto est une baseline non triviale (cf. ETH N2 du 2026-10-14 où le 1-day reversal était marginal). Le pipeline ML ne fait que sur-ajuster aux particularités du train sans capturer de structure prédictive stable.

3. **Le DSR est l'outil discriminant.** Avec un SR_hat ≈ -0.097 (lift vs baseline) et un E[max SR] substantial (autour de 0.1 pour n_trials=6), le p-value explose à 0.88. C'est précisément le scénario où un backtest « beau » serait rejeté par le DSR : sans cette étape, on aurait pu être tenté d'investiguer plus loin.

4. **Cause structurelle confirmée.** L'information microstructurelle crypto vit sur le tick, pas sur le bar 1-day. Voir note veille Easley SSRN 4814346 (2026-10-14) et BACKLOG item 15 : l'acquisition de données tick (Tardis / Kaiko / Databento) est le seul axe suivant qui pourrait produire un signal non arbitragué, et il nécessite le budget OK de Samuel + un nouveau seal de cutoff post-acquisition.

## 10. Verdict

**0 edge tradable net de coûts. Axe 6 clos. Aucune ledger hypothesis enregistrée.**

Le pipeline ML est conservé dans le code (module + tests) comme **outil de diagnostic falsification-first** : il peut être ré-utilisé si de nouvelles features ou un nouveau panel deviennent disponibles, avec les mêmes garde-fous (purged k-fold + DSR + preprocessing causal + baselines triviales obligatoires).
