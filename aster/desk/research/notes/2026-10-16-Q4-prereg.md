# Q4 — Bars and aggTrades (preregistration)

**Date**: 2026-10-16
**Item**: Q4 (research/QUEUE.md), free public import + bar reconstruction.
**Skills**: `lopez-de-prado-afml` ch02 (information bars), `tsay-analysis-financial-time-series` ch02.

## Hypothesis (mechanism-level, no number predictions)

1. AggTrades (tick-level, raw) on Binance Vision covers BTCUSDT and ETHUSDT monthly ZIPs from 2017-01 (BTC) and 2017-08 (ETH) up to present. Head requests on 2026-10-16 confirm 200 for BTCUSDT 2022-01 (443 MB), ETHUSDT 2022-01 (335 MB), BTCUSDT 2024-06 (354 MB).
2. The afml ch02 information bars (volume / dollar / taker-imbalance) can be reconstructed from aggTrades and produce a sampling that is more stationary than time bars on intraday microstructure: fewer fabricated empties, comparable sample size, predictable count.
3. The existing 5m/15m/1h/4h bars derived from R2 klines are correct in OHLCV but lose the signed-flow and tick-arrival information that Q6 / Q7 need. They stay as the temporal baseline; the new information bars are an *additional* sampling layer.

## Predictions (test families)

- **F1 (numeric)**: After cutoff enforcement (strict < 2024-07-01 UTC), the importer reads all rows from 2022-01-01 00:00:00 UTC through 2024-06-30 23:59:59.999 UTC and no later row. Verified by:
  - min(ts) ≥ 2022-01-01 UTC and max(ts) < 2024-07-01 UTC across the 60 partitions.
  - Test fails if a single timestamp ≥ cutoff survives.
- **F2 (numeric)**: Per-symbol, per-month row count lies in [N_min, N_max] where N_min/N_max are reasonable bounds. Documented but not asserted strictly (some years exceed orders for very active periods).
- **F3 (mechanism)**: Volume bars on BTCUSDT 2024-06 return a count between 5 000 and 50 000 bars (one bar per X BTC traded). Documented but not asserted strictly.
- **F4 (mechanism)**: The TakerImbalance feature on BTCUSDT 2024-06 1m bars has mean ≈ 0, std ∈ [0.1, 0.5], and contains ≥ 1 % zero entries (no-trade bars). Documented; not asserted strictly.

No edge claim, no Sharpe claim, no PnL claim. The predictions are about data integrity and sampling properties — *falsification criteria for the importer*, not for a strategy.

## Falsification

- Cutoff leak: any post-2024-07-01 row present in any partition → reject, rebuild.
- Manifest non-metadata-only: any record values (prices, qtys, trades) in `*.manifest.json` → reject.
- SHA-256 mismatch on any partition during `--sha256` audit → reject that partition.
- 5m/15m/1h/4h bars from R2 not re-validated against kline source → reject (must use the same `normalise_clock` + `build_bars` as Q1/Q2/Q3).

## Numbers / bounds (record-only)

- AggTrades schema = `[agg_trade_id, price, qty, first_trade_id, last_trade_id, transact_time, is_buyer_maker]`. Timestamp = `transact_time` (ms epoch). Boolean side = `is_buyer_maker` (True = buy lifted by taker that consumed the bid, i.e. aggressive sell).
- Storage: Parquet per `(symbol,month)` partition with `snappy` compression, columns `[transact_time:int64, price:float64, qty:float64, is_buyer_maker:bool]`. Manifest metadata-only: `{source, key, size_bytes, sha256, rows, start, end, timestamp_unit, cutoff_exclusive}`.
