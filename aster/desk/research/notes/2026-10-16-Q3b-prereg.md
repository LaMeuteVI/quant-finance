# Q3b preregistration — Perp klines, premiumIndex, markPrice, OI metrics (D5, ORANGE auto-approve)

**Written before any download.**

## 1. Why Q3b exists

Q3's 404s (see QUEUE Q3 + `data-sources.md`) came from the paths
tried, not from the archive itself. F1v2 needs a real **perp
close** series to earn the perp return on the hedged leg; Q3
established the funding store but never produced a perp close
panel. The five layouts we have not yet tested are listed in
QUEUE Q3b; the queue says "use the archive's `CHECKSUM` files" and
"document the exact URLs and HTTP codes" if everything fails.

## 2. Mechanism

USD-M (USDⓈ-M) perps on Binance publish four sibling time series:

- `klines` — perp OHLCV at 1m/5m/15m/1h/4h/1d; the perp **close**
  is the price the perp leg is marked to in P6's `perp_close`
  argument. The DoD for F1v2 needs the 1h bar.
- `premiumIndexKlines` — the mark price premium index; the
  difference `mark − index` is the basis that drives the
  next-funding rate and is what an F2-style crowding signal
  reads. Same bar grid as `klines`.
- `markPriceKlines` — the mark price (a 30-min EMA of the
  last-trade price). Useful as a stable reference for the
  perp leg in tests.
- `metrics/<SYM>/<SYM>-metrics-YYYY-MM-DD.zip` — daily file with
  **open interest** and **long/short ratio**. Available from
  ~2021-12 onwards (F2 needs OI for sizing/risk; F1v2 does not
  need it but Q3b will collect it since the cost is one HTTP
  call per month per symbol).

We are not changing the cutoff (2024-07-01 UTC) and not adding
holdout access. The same manifest + audit + cutoff discipline
as Q3 applies.

## 3. Scope (this item only)

What Q3b delivers:

1. **Perp OHLCV importer** (`aster.data.perp_klines.import_archive`):
   reads `data/futures/um/monthly/klines/<SYM>/1h/<SYM>-1h-YYYY-MM.zip`,
   enforces the cutoff, writes Hive-partitioned parquet at
   `data/r2/market/futures/um/klines_1h/symbol=<SYM>/year=.../month=.../part-0.parquet`
   plus a manifest with SHA-256.
2. **Premium index importer** (`aster.data.premium_index.import_archive`):
   same shape, separate destination
   `data/r2/market/futures/um/premium_index_klines_1h/...`.
3. **Mark price importer** (`aster.data.mark_price.import_archive`):
   same shape, destination
   `data/r2/market/futures/um/mark_price_klines_1h/...`.
4. **Metrics importer** (`aster.data.perp_metrics.import_archive`):
   daily ZIP with OI / long-short ratio, destination
   `data/r2/market/futures/um/metrics/symbol=<SYM>/year=.../month=.../day=.../part-0.parquet`.
5. **`aster.data.perp_store`** loaders: `load_perp_closes(symbols,
   bar_index)`, `load_premium(symbols, bar_index)`,
   `load_mark_price(symbols, bar_index)`. The loaders fill NaN for
   any time outside the data range (a bar with no perp observation
   is an off-hours bar — never raised against the call, just NaN).
6. **Audit CLI** `desk data audit-perp` (analogous to
   `desk data audit-funding`) checks: (a) every partition has a
   manifest, (b) SHA-256 round-trips on opt-in, (c) row count
   and time bounds match, (d) **no row at or after the cutoff**.
7. **`research/atlas/q3b_perp_data.json`** artefact: per-symbol
   coverage table (first month, last month, total rows, total
   bytes) for each of the four streams; a status field (`GREEN`
   if every layout returned 200 + matching CHECKSUM, `RED`
   otherwise with the exact URL + HTTP code per layout).

Universe for Q3b dev probes: BTCUSDT first (cheapest sanity
check), then the same 12 panel symbols as Q3 (BTC, ETH, BNB,
SOL, XRP, DOGE, LINK, AAVE, SUI, NEAR, plus LTC and ARB for
cross-checking). The full 12-symbol download only runs **after**
BTCUSDT returns 200 with a matching CHECKSUM and the importer
passes its unit test on a single file.

What Q3b does **not** deliver:

- No new hypothesis registered. No `H-*` ledger entry.
- No change to `risk/`, `execution/`, `policies/`,
  `config/risk_limits.yaml`, no live, no key, no order, no paper.
- No `holdout` sample reading.
- No F1v2 backtest. Q3b only provides the **data** F1v2 needs.

## 4. Falsification

Q3b is **falsified** (RED) if any of:

- All four layouts (`klines`, `premiumIndexKlines`, `markPriceKlines`,
  `metrics`) return 404 on `data.binance.vision` for BTCUSDT
  in at least one pre-cutoff month. In that case we document
  the exact URL + HTTP code per layout and stop; F1v2 stays
  blocked on paid L2 (Tardis / Kaiko / Databento = RED per D3).
- The archive's `CHECKSUM` file does not match the SHA-256 of
  the downloaded ZIP for at least one month. The integrity
  guarantee is the whole point of the discipline; a missing
  check is a RED.
- A downloaded partition contains any row at or after the
  cutoff (2024-07-01 UTC). The cutoff is enforced in the
  importer, not the loader, so a breach is an importer bug.

Q3b is GREEN when: BTCUSDT has at least one green month for
**each** of the four layouts (or, if a layout is missing for
all symbols, the exact 404s are documented and the loader
handles a missing layout by raising `FileNotFoundError` not
silently returning an empty panel); the importer unit tests
are green; the audit CLI is green; the artefact is written.

## 5. Numeric prediction

- The 1h kline archive for BTCUSDT averages ~30 kB/month × 60
  months = ~1.8 MB compressed → ~30 MB parquet. Across 12
  symbols: ~360 MB parquet for klines, comparable for
  premiumIndex, ~360 MB for markPrice, and ~12 MB for metrics
  (daily, smaller). Total Q3b on disk ≤ 1.2 GB.
- A successful BTCUSDT probe in the first month returns
  ~720 rows (1h × 30 days) with no NaN and a CHECKSUM that
  matches `sha256sum` of the downloaded file.

## 6. Order of operations (this item only)

1. Write prereg (this file).
2. Test the 4 layouts on `data.binance.vision` for BTCUSDT
   (one month each), with `curl -sS -I` for the `CHECKSUM`.
3. If any layout 404s for BTCUSDT, document and stop (RED).
4. Otherwise write the 4 importers and the 1 loader module.
5. Run BTCUSDT for the full pre-cutoff window.
6. Run the panel (12 symbols × 4 streams) after BTCUSDT is
   green.
7. `uv run pytest -q` green; audit green; artefact written.
8. Commit + push.
