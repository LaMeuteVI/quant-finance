# Q3 — Perpetual futures data, pre-cutoff (preregistration)

**Date**: 2026-10-16
**Item**: Q3 (research/QUEUE.md), free public import per D5.
**Skills**: `chan-machine-trading`, `hull-derivatives`, `grinold-kahn-apm`.

## 1. Mechanism (what we are testing)

The brief identifies funding-rate / basis carry as the best-documented
crypto risk premium (leveraged longs pay for the hedge). To study it
we need:

- **funding rate** at the 8-hour fixings (UTC 00:00, 08:00, 16:00);
- **mark price** and **premium index** at the same cadence for basis
  and mark-vs-index spread;
- **open interest** and aggregate long/short metrics for crowding;
- **perp 1-minute klines** for the carry backtest itself (spot leg
  already exists in `data/r2/`).

USDⓈ-M (Binance) is the venue. Funding fixings and mark rules are
documented in `chan-machine-trading` and `hull-derivatives`. The
funding rate is paid every 8h per contract; basis = perp mark − spot
index; carry = expected funding over the holding period, net of fees
and basis drift.

## 2. Question

For each symbol in the pre-cutoff R2 spot inventory (12 symbols),
what pre-cutoff USDⓈ-M data is freely available on
`data.binance.vision`? What can be imported today, with the same
provenance, manifest and cutoff discipline as the spot R2 store?

## 3. Falsification

If a particular (dataset, symbol) cell is reported as **absent** by
the probe, but a free public source (Binance Vision, ccxt REST)
returns a verifiable ZIP or JSON for the same symbol and window, the
probe is wrong and must be corrected before importing.

If the import succeeds for a (dataset, symbol) cell, the resulting
local Parquet partition must pass `audit_futures_umd` (analogous to
`audit_local` for spot R2): the file must round-trip SHA-256, the
declared row count and time bounds must match the Parquet content,
and no pre-cutoff symbol may land in `data/sealed/`.

## 5. Method (scope of this iteration)

This iteration covers what is *free and importable today*:

1. `data/futures/um/monthly/fundingRate/<SYM>/<SYM>-fundingRate-YYYY-MM.zip`
2. `data/futures/um/monthly/klines/<SYM>/1m/<SYM>-1m-YYYY-MM.zip`

Local store layout (Parquet, one file per symbol-month):

```
data/r2/
  market/
    futures/
      um/
        funding_rate/
          symbol=BTCUSDT/year=2020/month=01/part-0.parquet
        klines_1m/
          symbol=BTCUSDT/year=2020/month=01/part-0.parquet
```

With a sibling `*.manifest.json` recording
`{source, key, size_bytes, sha256, rows, start, end, timestamp_unit}` —
no record values, same schema as the spot R2 store.

If the probe shows `premiumIndexKlines`/`markPriceKlines`/`metrics`
are reachable on a different path later, add separate folders.

The 12-symbol inventory is a starting point; symbols whose funding
file is 404 pre-cutoff (e.g. SUIUSDT before 2023-05) are skipped
with a row in `research/atlas/data-sources.md`.

## 7. Limits and risks

- `fundingRate` is a sparse series (one row per 8h fixing) — ~3
  rows/day per symbol. The full pre-cutoff history per symbol is
  small (< 5 MB ZIP compressed per year). Total storage for the 12
  symbol panel is small.
- Perp `klines 1m` is heavier (~1.8 MB / month / symbol) and
  overlaps the spot klines in date range but not in fields (no
  `taker_buy_*` fields). It is required to compute the spot-vs-perp
  basis at minute resolution.
- We deliberately do NOT import any post-cutoff partition: the
  cutoff is exclusive and the sealed store stays empty for Q3.
- The default rate limit of `data.binance.vision` is generous; if
  it is hit, the importer pauses with exponential backoff and
  resumes without dropping files (atomic write, partial preserved
  on failure).
- FundingRate files before 2019-01 may be empty or missing; the
  importer skips empty ZIPs and records them as "absent" rows.
