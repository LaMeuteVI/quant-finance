# P5 — Walk-forward and PBO by default (preregistration)

**Date**: 2026-10-16
**Item**: P5 (research/QUEUE.md, Block P).
**Skills**: `quant-backtest-hygiene`, `lopez-de-prado-afml` ch11-12.

**Mechanism**.
Walk-forward is the standard "fit on the past, evaluate on the future"
loop (AFML ch. 11). Purging + embargo eliminate the serial-correlation
leak that a naive rolling window leaves behind. PBO (Probability of
Backtest Overfitting, Bailey-Borwein-Lopez de Prado-Zhu 2016 / AFML
ch. 12) is the right diagnostic when a hypothesis has been
parameter-swept; the same Sharpe is not a fair benchmark across
configurations that have been tuned on the same dev sample.

**Statement**.
Every dev `pipeline.run` adds two new blocks to `report.json`:
* `walk_forward`: a per-fold Sharpe / drawdown table built from
  `validation.cv.walk_forward` with defaults `train_bars=252`,
  `test_bars=63`, `embargo_bars=5`, `expanding=True` (quarterly
  retraining for daily data, with one trading-week embargo).
* `pbo_cscv`: the PBO across a `params_grid` if one was supplied;
  uses `validation.pbo.pbo_cscv` with `n_splits=16`.

**Falsification**.
The pipeline is broken if (a) the walk-forward table is empty on a
run with ≥ 315 bars, (b) the PBO block is present without a
`params_grid` (false positive), (c) the PBO is `None` when a
`params_grid` was supplied and the strategies produced non-NaN
returns, (d) the walk-forward train / test windows overlap, or
(e) the embargo is zero in the P5 contract (the legacy default was
zero and is wrong for crypto daily).

**Prediction**.
* `pbo_cscv` ≤ 0.3 on the very first dev run that sweeps a
  parameter that is genuinely free (e.g. `lookback` ∈ {20, 60,
  120}). Higher than that and the strategy is not yet a candidate.
* The walk-forward table has ≥ 4 folds on 3 years of daily data
  with the defaults above.
