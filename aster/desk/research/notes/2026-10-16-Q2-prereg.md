# Q2 — Missing universe members (preregistration)

**Date**: 2026-10-16
**Item**: Q2 (research/QUEUE.md), depends on Q1 (now DONE).
**Scope**: free public import only (D1, D3).

## 1. Mechanism (what we are testing)

The brief section 2 lists the canonical research universe:

- RENDERUSDT, ONDOUSDT, PUMPUSDT (spot)
- HYPEUSDT (perp USDⓈ-M)

plus the 12 symbols already imported from the R2 bucket:

BTCUSDT, ETHUSDT, SOLUSDT, AAVEUSDT, DOGEUSDT, SUIUSDT,
XRPUSDT, BNBUSDT, LINKUSDT, NEARUSDT, XMRUSDT, FETUSDT.

The exploration must cover all of them. Listing dates known from the
brief:

- RENDER (Render Network): listed on Binance 2023-06.
- ONDO: listed on Binance 2024-04.
- PUMP: launched 2025; never on Binance spot before 2024-07-01.
- HYPE (perp USDⓈ-M): listed on Binance 2025-05; pre-cutoff history
  does not exist.

## 2. Question

For each missing symbol, does a pre-cutoff partition exist in either
the local R2 store or `data.binance.vision`? If yes, import it into the
pre-cutoff `data/r2/` store (free public data, GREEN). If not, record
the absence in `research/atlas/data-sources.md` and route the symbol
to the sealed store (post-cutoff only) or the perp channel (Q3).

## 3. Falsification

If the inventory script can return a verifiable Parquet file path
(pre-cutoff) for any of these symbols, the preregistration must
import it through `desk data import-r2` and `desk data audit-r2
--sha256` must pass on it. If the script returns `NoSuchKey` against
the official listing endpoints, the symbol is recorded as "absent"
and treated as:

- holdout-only panel member (PUMP, ONDO if 2024-04→2024-06 missing);
- perp channel (HYPE, addressed by Q3).

## 4. Numerical prediction

I expect **zero pre-cutoff spot partitions** for RENDER, ONDO, PUMP in
both the local R2 bucket and `data.binance.vision`. HYPE has no
pre-cutoff spot data at all (perp-only listing post-cutoff).

If the script returns ≥1 pre-cutoff spot partition for any of the
three, the inventory was wrong, and the prediction is falsified.

## 5. Method

A reproducible probe (`scripts/probe_universe.py` to be added) that:

1. Lists `data/r2/market/spot/klines_1m/` for local pre-cutoff
   partitions of RENDER, ONDO, PUMP, HYPE.
2. Probes `https://data.binance.vision/data/spot/monthly/klines/<SYM>/1m/`
   for the same symbols.
3. Records results as a CSV with columns
   `{symbol, channel, exists, sample_key_or_None, error}`.
4. The script writes no data to `data/` and emits no record values in
   logs (probe error messages only).
5. Unit test verifies the probe is deterministic for the listed
   endpoints and refuses network I/O if env var `ASTER_OFFLINE=1`.

`scripts/probe_universe.py` lives under the desk and is GREEN to
write (data acquisition, no risk/ or execution/ touched).

## 6. DoD mapping

- `research/atlas/data-sources.md` updated with the proposal outcome
  (one row per probed symbol).
- Probe script + test committed; `uv run pytest -q` green.
- MAP.md, BACKLOG.md updated if the result closes a class or opens
  a new one.

## 7. Limits

- The probe only tests two channels (local R2, data.binance.vision).
  Other free public sources (ccxt `binance` REST, CoinGecko free
  tier, on-chain aggregators) are NOT probed here; they belong to a
  later item if the brief asks for them and they remain free.
- Binance delistings: the inventory probe cannot distinguish "never
  listed" from "listed then delisted and removed from the public
  archive". D5 (perps in scope) and the brief's note that the 14/15
  universe is survivorship-biased already say so.
