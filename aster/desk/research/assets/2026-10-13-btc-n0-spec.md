# BTC N0 asset dossier — reproducible specification

**Scope:** Binance spot `BTCUSDT`, local R2 1-minute klines only; descriptive market-data dossier, not a hypothesis, signal, alpha claim, cost forecast, or backtest.

**Exploration boundary:** include timestamps `>= 2017-08-17T04:00:00Z` and strictly `< 2024-07-01T00:00:00Z`. Never read, merge, or infer from later market data. Treat each one-minute record as the interval beginning at `open_time_utc`.

## Source and provenance

- Canonical input: `data/r2/market/spot/klines_1m/symbol=BTCUSDT/year=*/month=*/part-*.parquet` plus each adjacent `.manifest.json`.
- Required source schema: `open_time_ms`, `open_time_utc`, `close_time_ms`, OHLC, `volume`, `quote_volume`, `trades`, `taker_buy_base`, and `taker_buy_quote`.
- First reproduce the partition audit, including manifest SHA-256 verification:

```bash
uv run desk data audit-r2 --symbols BTCUSDT --sha256
uv run desk data quality-r2 --symbols BTCUSDT --max-frozen-share 0.05 --min-coverage 0.99
```

Save the unedited JSON stdout with the dossier. Record the command, UTC run time, code revision, manifests' SHA-256 values, row/partition totals, source span, and `cutoff_exclusive`. No hand edits to source data; all exclusions must be reported as counts and timestamp ranges.

## Definitions and handling

| Item | Definition | Treatment |
|---|---|---|
| Present minute | A unique, UTC, exact-minute `open_time_utc` record strictly before cutoff. | Count; do not fabricate absent minutes. |
| Missing minute | Calendar minute between the first and last present minutes with no record. | Count globally/monthly; list every contiguous gap and its duration. Not a frozen minute. |
| Frozen minute | Present minute with `trades == 0`. Report `volume == 0` separately as a consistency check. | Retain in the raw coverage panel; exclude from trade-conditioned summaries only, with the exclusion count shown. |
| Accounting inconsistency | `trades > 0` and `volume == 0`, negative volume, non-positive OHLC, `high < low`, or close outside `[low, high]`. | Fail the affected quality section; do not silently repair. |
| Taker buy flow | `taker_buy_quote` (primary, USDT) and `taker_buy_base` (cross-check, BTC) supplied by the kline. | It is buyer-initiated **reported volume**, not a predictive order-flow label. |
| Taker-flow imbalance | `(taker_buy_quote - (quote_volume - taker_buy_quote)) / quote_volume`, defined only when `quote_volume > 0`. | Report its distribution and counts; never fill or assign a value to zero-volume/frozen minutes. |
| Notional liquidity proxy | `quote_volume` per minute, in USDT. | Describe realised venue turnover only; it is not order-book depth, executable capacity, impact, or consolidated BTC liquidity. |

Use `quote_volume` for all USD/USDT volume statistics. Check `0 <= taker_buy_quote <= quote_volume` (within documented numeric tolerance); report violations. Check duplicate/out-of-grid timestamps before any aggregation. Do not resample gaps to zero volume.

## Required descriptive outputs

### 1. Coverage and integrity table
One row for the full sample and one per UTC calendar month:

- first/last present minute; expected, present, missing counts; coverage = `present / expected`;
- partition count, source rows, duplicate/off-grid count, and all integrity-error counts;
- frozen count/share, zero-volume count/share, and `trades > 0 & volume == 0` count;
- every contiguous missing interval: start, end, and number of minutes (appendix or CSV if large).

### 2. Liquidity / activity profile
For all present minutes and separately for trade-active minutes (`trades > 0`):

- `quote_volume`, base `volume`, and `trades`: total, mean, median, p25, p75, p95, p99, maximum, and zero share;
- daily `quote_volume` and trade-count totals: p05, p50, p95, min, max; identify dates tied to extrema;
- concentration: share of total `quote_volume` in the largest 1%, 5%, and 10% of minutes; report the deterministic rule `ceil(p × N)` and tie handling;
- UTC-hour profile: mean and median minute `quote_volume`, median `trades`, frozen share, and each hour's share of all sample `quote_volume`. Hour denominators use present minutes only.

### 3. Taker-flow profile
For trade-active minutes with positive `quote_volume`:

- total quote volume, taker-buy quote volume, inferred taker-sell quote volume (`quote_volume - taker_buy_quote`), and taker-buy share (`taker_buy_quote / quote_volume`);
- minute imbalance: valid-minute count; mean, median, p05, p25, p75, p95; fraction positive, negative, and exactly zero;
- same taker-buy-share and imbalance summaries by UTC hour and UTC calendar month;
- validation counts for missing/non-finite values and values outside `[0, quote_volume]`. Treat a violation as a quality finding, never clip it without disclosure.

### 4. Frozen-minute profile
- frozen count/share by UTC hour, UTC calendar month, and weekday (UTC);
- run-length distribution of consecutive frozen minutes: number of runs, p50, p95, max, and the start/end of every run of at least 5 minutes;
- joint table for frozen minutes, missing minutes, and `quote_volume == 0` minutes. These categories must remain distinct.

## Reproducibility contract

1. Load only through `aster.data.r2_klines.read_local("BTCUSDT")` after a successful `audit-r2`; this enforces approved inventory and the fixed cutoff.
2. Use UTC-aware timestamps, stable sorting by timestamp, and explicitly fail on duplicates.
3. Persist a machine-readable `btc-n0-summary.json`, `btc-n0-coverage-by-month.csv`, `btc-n0-hourly-profile.csv`, `btc-n0-flow-by-month.csv`, and `btc-n0-gaps-and-frozen-runs.csv` beside the human-readable dossier. Include formulas, input manifest hashes, code revision, command line, and output-file hashes in `btc-n0-summary.json`.
4. All percentile interpolation must use the installed pandas default and state its version; all displayed counts are integers and shares are stored unrounded (round only for presentation).
5. The dossier contains no return tests, labels, forward outcomes, correlations to returns, strategy rules, capacity allocation, or pass/fail alpha verdict.

## Current gating observation (not a market conclusion)

On 2026-10-13, `audit-r2 --symbols BTCUSDT --sha256` verified 83 partitions and 3,605,599 rows in the approved pre-cutoff store. The quality command reported 99.7631% coverage, 24,003 frozen bars (0.6657%), 8,561 missing minutes, and zero `trades > 0 & volume == 0` inconsistencies, but returned `ok: false` because it found 21,602 timestamps off the minute grid (and 34 gaps, largest `1 days 09:31:14.789000`).

Therefore N0 descriptive aggregation is **blocked pending timestamp-unit/normalisation diagnosis**. The frozen-share and coverage thresholds alone do not override a timestamp-integrity error. This is a data-quality disposition only, not an inference about BTC liquidity, flow, or tradability.
